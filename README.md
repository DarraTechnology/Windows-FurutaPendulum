# DarraFurutaPendulum

Furuta 旋转倒立摆 EtherCAT 控制示例，包含能量起摆、平衡控制、回中、参数管理、WinForms 界面与命令行入口。适合作为 Darra EtherCAT Master 在计数类 IO 与运动控制场景下的完整使用示例。

## 环境与依赖

- Windows x64，.NET Framework 4.7.2（`net472`）。
- NuGet 依赖：`Darra.EtherCAT.Master` **2.13.23**。
- 运行需要已通过官方安装器安装并绑定到对应 EtherCAT 网卡的 **DarraRT_Eth** 驱动，以及与现场总线匹配的配置文件。
- 真机操作前必须确认硬接线急停、STO、机械限位和现场清场有效。

## 构建

```powershell
dotnet build -c Debug -p:Platform=x64
```

可执行文件输出到 `bin\x64\Debug\net472\FurutaPendulum.exe`。无参数启动 WinForms 界面；命令行模式使用 `--cli`。

## 主要 CLI 命令

| 命令 | 用途 |
|---|---|
| `connect` | 连接 EtherCAT 总线并检查现场配置 |
| `enable` | 满足安全前提后使能摆臂 |
| `recenter` | 回到行程中点并重新居中 |
| `swingup` | 执行自动起摆并在满足条件后交接到平衡控制 |
| `balance --seconds 30` | 保持平衡 30 秒 |
| `stop` | 受控停止并退出使能 |

单次执行示例：

```powershell
.\bin\x64\Debug\net472\FurutaPendulum.exe --cli "connect; enable; recenter; swingup; balance --seconds 30; stop" --yes
```

也可用 `--cli` 进入连续命令模式，或用 `--help` 查看完整参数。各命令必须在真实硬件和有效安全条件下使用。

# 旋转倒立摆 Furuta（广成 GCAN-8200 计数 + GreenIOT GR-EC01/EC1 步进摆臂 · 500 µs / 2000 Hz）

**这是倒立摆闭环示例**：摆杆角 θ 由 **广成 GCAN-8200 计数切片**读摆杆编码器得到（台架现用 **GC1602** AB 正交计数，**GC1502** 脉冲计数走兼容 / 备选路径），摆臂角 φ 由同一总线上的 **GreenIOT GR-EC01 / EC1 系列步进驱动器**以 CSP（`0x6060 = 8`）驱动，摆臂从站用 `--arm-slave` 指定或自动判定。控制律以 **θ 为闭环量**（编码器实测），摆臂按控制输出做位置跟随；**步进本身是开环的**（EC1 手册 0x2100 明写只支持开环），`0x6064` 是驱动器内部指令位置的积分估计，不是电机轴实测——这一点决定了下文的安全边界。总线周期 **500 µs（2000 Hz）**，每个周期算一次 `0x607A`。同一个 exe 给两条路：**UI（WinForms）** 人在旁边点按钮，**CLI（无头）** 给脚本、CI、远程 shell 驱动；两条路共用同一个控制层 `PendulumEngine`，安全联锁只有一套，不会出现「UI 里能起摆、命令行里起摆行为不一样」。

本目录是 Windows x64 开源案例，演示的是「计数类 IO 从站 + CiA 402 步进轴同总线共存」与「能量起摆 → 切平衡闭环」的完整链路。**真机总线是 6 从站共享总线**（见下「设备信息」），本案例只动自己的摆臂/计数从站，旁观从站不碰也不惧。它不替代硬接线急停、STO、限位和机械清场，也不能当成仿真通过就等于现场安全。

项目基于 .NET Framework 4.7.2，引用 `Darra.EtherCAT.Master` NuGet 包，产物只有 `bin\x64\<Configuration>\net472\`。

## 设备信息

| 项 | 内容 |
|---|---|
| 厂商 | 广成 GCAN（VendorId `#x00000E0D`）+ GreenIOT 步进（VendorId `#x0AB5`）；ESI 见仓库根 `其他依赖文件/ESI/GCAN-8200.xml` 与 `GreenIOT_GR-EC01.xml`（该目录被根 `.gitignore` 排除，**克隆后不在仓库里**；仓库内已跟踪的同一份副本在 `测试项目/TEST_SDK_CSharp/ESI/`，MD5 相同） |
| 耦合器 | **GCAN-8200** MDP 模块化耦合器，整机一个 EtherCAT 从站（计数切片、可选 GC2008 DO 都插在它上面） |
| 计数切片 | **GC1602（台架现用，AB 正交）** 2 通道计数：TxPdo `0x1A03`：`0x6003:1` / `0x6003:2` 两路计数 **DINT32 有符号**（共 8 B）；ESI 里声明 RxPdo `0x1600`：`0x7000:1` / `0x7000:2` 两路 BOOL 复位位 + 14 bit 填充（共 2 B），但**当前固件上 `0x1600:00` 恒 abort `0x06020000`**（`0x1601..0x1630` abort `0x05040000`），主站把输出方向按 0 配置（`GcanOutputsMapped=false`），清零实际走软件置零。**GC1502（兼容 / 备选）** 频率计数 4×UDINT：`0x6003:1` CH1 Count、`:2` CH1 Frequency、`:3` CH2 Count、`:4` CH2 Frequency（共 16 B），**RxPdo 无（没有复位命令）**。对象字典 / 字段细节以 `--help` 与运行时诊断输出为准。当前台架实况见下「当前台架（2026-11-14）」 |
| 在位模块表 | **`0xF050`（Module detected list）**：`:00` = **表项总数（含结尾字符）**，`:01..:N` = 各表项 UDINT。末项 **`0x00000001` 是结尾字符（terminator），不是模块**，真实模块 = `sub0 - 1`（判据按值 + 位置：仅末项 == 1 时剔除，末项是 2008/1502/1602 时保留）。现场实测 `0xF050 = [2, 1502, 1]` ⇒ 真实模块只有 GC1502 一个 ⇒ 过程映像 **In 16 B / Out 0 B**，与设备 `0x1C13` 只映射 `0x1A03` 吻合（这是 **2026-10-29** 的读数；**2026-11-14 起计数槽位是 GC1602，ident `0x0642`**，`0x0642` = 十进制 1602、`0x05DE` = 十进制 1502，实读表项与字节数以连接后的运行时诊断为准）。总字节 = 各真实模块按 ESI 模板累加的**推导值**，与主站实测交叉核对，不写死总数 |
| 摆臂驱动 | **GreenIOT GR-EC01 / EC1 系列步进驱动器**（独立从站，VendorId `0x0AB5`），CSP 模式：`0x6040` 控制字 / `0x6060 = 8` / `0x607A` 目标位置 / `0x6064` 指令位置估计 / `0x606C` 实际速度（rpm）。**EC1 是开环步进**，0x6064 不是编码器实测。共享总线上用 `--arm-slave <n>` 指定摆臂从站（不给 = 自动判定，候选必须唯一） |
| 摆臂 PDO | RxPDO `0x1600` **7 B**：`0x6040:16@0` → `0x607A:32@2` → `0x6060:8@6`；TxPDO `0x1A00` **17 B**：`0x603F:16@0` → `0x6041:16@2` → `0x6064:32@4` → `0x606C:32@8` → `0x60FD:32@12` → `0x6061:8@16`。**条目顺序不能照旧写成 0x6040→0x6060→0x607A**（0x6060 落在偏移 2 会被当成目标位置高字节，电机直接跑飞） |
| 轴数 | **1 电机 + 1 计数通道** |

**闭环量是摆杆角，不是电机轴**：θ 来自摆杆编码器（GC1502/GC1602 计数切片），控制律据此算摆臂目标；`0x6064` 只是驱动器内部指令位置的积分估计，EC1 没有电机轴编码器（手册 0x2100：「本产品只支持开环」）。所以跟随误差 S2、无运动门、`0x607A` 阶跃护栏、软限位都只能拿 **指令 vs 指令估计** 做一致性检查，**丢步 / 堵转 / 越障静默不可见**；唯一线索是 `0x603F = 0x8401`（位置超差，不可清除，由 S4 兜住）。**软限位和跟随误差都不能当真实机械安全边界**，硬接线急停 / STO / 机械限位必须独立有效。换闭环步进（带电机轴编码器）时，`0x6064` 的语义才会变成实测；本案例不假设这一点。

**共享总线**：真机总线是 **6 从站共享** —— **自有两台**：① GCAN-8200 IO 耦合器（计数槽位插 **GC1602** 编码器切片，接摆杆编码器；GC1502 是兼容 / 备选切片；GC2008 DO 若在位也只写 0）；② GreenIOT GR-EC01/EC1 步进（摆臂电机）。**其余 4 台是旁观从站**（Beckhoff EK/EL 链等）：本案例不碰、也不怕它们在总线上，它们的 WKC / 状态只进诊断，不触发本案例的 Fault。摆臂从站用 `--arm-slave <n>` 选（1 基；不给 = 自动判定；候选不唯一 / 越界 / 指到 GCAN = 拒绝连接并列候选清单）。示例里的 `--arm-slave 6` 只是真机拓扑的一个取值，**换拓扑必须按实际序号替换**，或直接不给让程序自动识别。

**两种切片分开说，不一刀切**：台架现用 **GC1602**（AB 正交，DINT 计数带符号、天生辨向）；**GC1502 走兼容 / 备选**（脉冲计数型，UDINT 无符号，`FreqCh1` 频率通道是**平均量**，**仅作 ω 交叉校验**——不当位置源、**不进控制律、不能当 dθ/dt**）。**零点语义**：GC1602 在 ESI 里有 Reset Counter（`0x7000:1`），但这块固件上 `0x1600:00` 恒 abort `0x06020000`、主站把输出方向按 0 配置，**硬件复位在当前固件 + 主站路径下不可达，实际走软件置零**；**GC1502 本来就没有复位命令，`zero pendulum` 同样是软件置零**（把当前计数设为零点基准）。切片 PDO 的 `Index` 全是 `DependOnSlot`，**过程映像偏移随槽位变化**，字段类型与顺序固定，绝对偏移以现场 GUI 扫描导出的 `.deni` 为准；连接后 PreOp 回读映射校验，对不上直接 fail closed。GC1502 / GC1602 的对象字典 / 字段细节以 `--help` 与运行时诊断输出为准。

### 当前台架（2026-11-14）

台架的计数切片换了：现在装的是 **GC1602**，10-29 记录的那块 GC1502 已经不是当前在用的切片。下面几条都可以逐条核对，证据写在括号里。

1. **台架 = GCAN-8200 耦合器 + GC1602 编码器切片。** 代码侧的记录在 `Darra_EtherCAT_Drive\main\core\config\highlevel_ext.c`（`GCAN-8200 + GC1602 ident 0x0642`；GC1502 的 ident 是 `0x05DE`）。10-29 的「槽位 2 = GC1502 / 全机无 GC1602」结论已经作废。
2. **GC1602 在 ESI 里的真实结构**（`其他依赖文件\ESI\GCAN-8200.xml`）：TxPDO `0x1A03` 是两路 `0x6003:1` / `0x6003:2`，都是 **DINT 32 位有符号**计数；RxPDO `0x1600` 是两路 `0x7000:1` / `0x7000:2` BOOL 复位位 + 14 bit 填充。**没有 Z 相，也没有锁存对象。**
3. **这块固件上 `0x1600:00` 恒 abort `0x06020000`**（`0x1601..0x1630` abort `0x05040000`），主站把输出方向按 0 配置、`GcanOutputsMapped = false`。所以「清零」走的是**软件置零**（把当前计数锁成零点），不是硬件 Reset —— 硬件复位在当前固件 + 主站路径下不可达。
4. **GC1502 的能力边界**：官方口径是**单端 5–30 V** 脉冲计数、32 位 **UDINT 无符号**、**无 AB、无方向**，只有 RST 清零（ESI 里没有 RxPdo 复位命令）。它做不了双向摆角闭环，只能做单向测速 / 计数。
5. **GC1602 的官方口径**：**差分 A/B、5–24 V、≤3 mA/通道、500 kHz**（旧选型表里的 200 kHz 已过时，以最新手册为准）。**官方没写 RS422 / Line Driver**，**无 Z 相**。
6. **现场编码器（2026-11-14 用户确认）**：**24 V 单端**，只有 **24+ / 0V / A / B / GND** 五根线，无互补信号、无 Z 相。所以「编码器 → GC1602 差分输入」怎么接**还没定**，既不是「直接接就行」，也不是「必须换模块」。两条走法待选：
   - ① 若 GC1602 手册允许单端接法（A → A+、A− → 0V 参考），可以直接接；
   - ② 否则加 24 V 单端 → 差分电平转换，或换差分输出编码器。

   **电平确认前不要上电试接**：差分输入直接灌 24 V 单端有损坏风险。

还有一条跟着变：摆杆每转计数按 **GC1602 AB 四倍频口径**标定为 **2400 count/rev**（600 线 × 4，现场实测自然下垂 ≈ 0、倒立 ≈ 1200）；旧的 600 是 **GC1502 脉冲计数口径**（不乘 4），套到 GC1602 上会让角度偏 4 倍，已从默认值和参数文件迁移逻辑里清掉。`status` 的「摆杆 ω 交叉校验」行在 GC1602 上没有频率计，显示「不可用」是正常结果。

### 2026-11-20 实机结论（台架 192.168.3.120）

这一轮改的是控制层与台架 DENI，全部有现场数字。详细推导与调参边界见 `内部文档/参数与调参规范.md` §1.5 / §2.3 / §3.2 / §3.3 / §5.3 / §5.5 / §7.7。

- **ω 估计去滞后**：旧实现取 40 ms 线性拟合的**窗口质心斜率**，等效 20 ms 之前的速度——同一拍实测 `ω=15.62`、`ω_est=17.94`（差 2.32 rad/s）；离线用 α=−115 rad/s² 复现，旧算法得 20.27（真值 18.000）。现在改**二次拟合取窗口末端斜率**，同条件误差 0.000。能量估计因此少偏约 0.45 J，而能量控制带宽只有约 0.05 J。
- **能量注入去直流**：`-u_E·softSign(ω·cosθ)` 一个摆动周期有净推力，摆臂 40 s 漂 17 圈（−40290 counts）；提周期到 500 µs、开正弦泵都压不住。现在用 τ=1 s 一阶低通估计直流并在注入拍扣除，漂移降到 90 s 1.6 圈。
- **软中心带**：`center_band_rad=3.6` 太小，摆臂频繁进「回中」、注入被反复掐断，起摆 58 s；放到 **20 rad** 后起摆 **13 s**。出厂默认已改为 **20 rad**（参数文件缺键 / 填 0 按 20 补齐；旧出厂整块被识别时也按 20 载入；用户显式写入 3.6 原样保留，不做运行时钳位）。现场改：CLI `setswingup --center-band <rad>`，或 UI「PID 调参… → 控制参数」里的「软中心带 CenterBandRad」；值随 `save-config` / 「保存参数」落盘。
- **抽取与注入解耦**：共用 `Ke` 时，`Ke` 为了顶满 `AMax` 要取到 700，0.03 J 超调就产生 21 rad/s² 刹车、瞬间顶满抽取上限；`energy_extract_ratio` 0.30 / 0.50 时能量 60 s 都攒不起来。新增独立 `ExtractGain`（抽取增益 = 能量超过目标时的刹车出力上限，单位 rad/s² per J，**默认 60**，范围 ≥0；0 = 未配置按 60 生效；负值 / 非有限值在 CLI 写入时拒收，参数文件载入时按 60 修正并提示），刹车量与超调成正比。改法：CLI `setswingup --extract-gain <值>`、参数文件 `swingup.extract_gain`、UI「控制参数」对话框；当前值会出现在 `status` 的「起摆参数」行、`dashboard` 的「能量整形」行，以及 `--json` 的 `setswingup` 回执 / `dashboard` 帧里的 `extractGain` 字段。抽取权限用 `setswingup --energy-extract`（默认 0.20，不要往 0.3/0.5 调）。
- **起摆可靠性（同参数多次结果不稳）**：根因是①能量泵把 `φ̈` 二次积分成位置参考后，速度顶到安全限速 20 rad/s，参考加速度被拍成 0，泵相位与摆杆脱开；②近直立淡出把顶部注入压到 8 rad/s²，能量在 E*−0.02 J 与摩擦打平；③捕获门用 `|φ| ≤ 0.6` 绝对角，而失败样本掠顶时摆臂在 −4.7 rad。现在：泵权限按执行器包线收紧（`|φ̇| ≤ 0.66·ω_n`、`|φ̈| ≤ min(AMax, 0.66·ω_n·ω_n)`）、能量环加积分补摩擦、**只在下降侧** `|ψ| ≤ 0.60 且能量接近捕获窗时进「准备」段（停泵 + 摆臂速度伺服回起始位，上行侧不刹车）、硬捕获门之上再叠**提交软上限 `|φ̇| ≤ 3.0 rad/s` + `|ω| ≤ 0.8 rad/s`** 并用漏桶计数交棒。离线 20 组初始条件：改前 2/20（且两个成功都是「初始就在直立」的退化样本，真正摆起 18 组全失败）；改后 20/20。
- **近直立淡出下限不得低于 0.35**：低于它泵在顶部推不过摩擦，能量会卡在捕获窗前（旧值 0.15 正是「E 停在 1.5~1.6 J、60 s 超时」的原因之一）。参数文件里更低的旧值在载入时按 `MinThetaFadeFloor` 替换并留 warning；`theta_fade_start_rad` 也不要抬到 1.2 以上（会把该冲上去的那一脚一起削掉）。
- **DC 默认关闭、周期下限 500 µs**：程序现在**默认不武装摆臂从站 DC**（按 FreeRun 运行；从站报告 DC 能力时显式 `DisableDC`，防止 SDK 自动策略又开回来），不需要改 DENI。需要 SYNC0 同步的现场用 CLI `--dc-sync`（GUI 无命令行旗标时用环境变量 `FURUTA_DC_SYNC=1`）显式打开；`--no-dc-sync` 用于覆盖环境变量的启用值。优先级：**CLI 旗标 > 环境变量 > 默认关闭**。关 DC 时总线照样进 OP，使能耗时 **166 ms → 87 ms**；打开后仍按 `HasDC` / `ConfigureDC` / `Sync0Armed` 硬门校验，未获确认就拒绝升态。250 µs（4 kHz）不可用：`InputsSliceMapping` 抛「PDO 输入映射不可用」，内核日志报「同一周期内重复通知同一个 PDO 输入缓冲区」。
- **`zero` 自动落盘**：CLI `zero arm` / `zero pendulum` 落定后自动增量写盘，回执带 `persisted`；`zero pendulum` 同时把 360° 点按同一圈量平移到新 0° 点上（回执 `pendulum360Rebased` / `calibrationNote`），清零前后角度连续、不会跳圈；旧版只改内存，换进程后摆杆零点不一致会拒绝使能（摆臂偏移现在按每次使能重新锁零，不再阻断）。
- **`normalize` / `recenter`**：**每次使能**与 `zero arm` 都只把当前位置定义成 φ=0、不搬软限位，反复在偏一侧的位置使能 / 设零会让可用行程越跑越少。`normalize` 把当前 raw 设成新零点并把左右限位按同一 delta 平移（跨度不变）；`recenter` 先开到行程中点再居中规整化。两者都会自动落盘。
- **`calibrate-radius`**：四相 ±加速度脉冲 + 二次拟合实测 `r/l`，成功后写入 `limits.radius_ratio` 并落盘。台架实测 `r/l=0.24 / Ka=900` → `(r/l)·Ka=216 > g/l=81.8`（2.6 倍结构裕量）；离线数学验证真值 0.24 时估计落在 0.228~0.249。
- **平衡仍未解决**：起摆能进提交条件并切平衡，但平衡接管后约 **0.26 s** 就发散（`ThetaOverrun` / `BalanceLost`）。已排除增益大小、符号、捕获臂速门限、执行权限、结构稳定性。不要把上面的起摆改善读成“平衡已可用”。

## 控制语义

- **坐标**：θ = 0 是摆杆自然下垂，直立点 θ_eq = π；φ = 0 是摆臂**起始位置**（= 开启时坐标 0）。遥测里给的是偏离直立角 `wrapPi(θ − π)`。
- **开启即自动归零（使能时编码器坐标 = 0）**：`enable` 走完 `0x6040` `06→07→0F` 并确认 `0x6061 = 8` 之后，两路编码器坐标**自动**归零——摆杆计数基准 + 摆臂 `0x6064` 基准同时建立。**摆臂零点每次使能都重新锁成当前 `0x6064`**（2026-11-20 语义：现场的“中心”= 本次使能位置；软限位绝对 counts 不随零点移动；`recenter` 回中流程例外保留旧中心）。**摆杆零点**若用「摆杆零点 (下垂 0°)」显式设过，就沿用保存的绝对计数（跨越重启有效，且不发 GC1602 硬件复位）；没设过才把当前计数锁成 θ=0。摆杆 raw 与保存零点不一致会阻断使能 / 起摆（要人确认），摆臂 raw 偏差不再阻断。**使能前把摆杆放到自然下垂、摆臂停在期望起始位**——姿态不对就以正确姿态重新使能。
- **电机在所有阶段尽可能保持在起始位置 0**：待机 hold **0**、起摆泵动围绕 **0**、平衡 `glide_base` 向 **0** 软滑、`stop` 受控停先回 **0** 再断使能（2 s 预算）。**回中让路给平衡**的裁定不变——软回中速率不超过 0.3 rad/s（θ 贴直立时 0.6 rad/s），一旦要稳摆杆，回中立刻让位，只是目标锚恒为 0。界面上「相对零点」就是当前关节计数距起始位置 0 的偏移（原始 counts）。
- **保持位置 = ±1200 count（= 180° 直立）**：摆杆编码器 **2400 count/rev**（600 线 × AB 四倍频，1 count = 0.15°），直立点就是 ±半圈。`+1200`（+π）与 `-1200`（−π）在 wrap 语义下是**同一个直立点**，摆杆从哪一侧甩上去都能就位稳住（控制误差 `wrapPi(π−θ)` 两侧线性化一致）。**起摆全自动**：能量泵从垂位（坐标 0）一路甩到保持位，**不需要人工扶摆 / 助力**；起摆方向不指定，哪侧能量够上哪侧。
- **起摆用单律能量法**：`φ̈ = −u_E·sign(ω·cosθ)`——**负号是关键**，取正号是抽能方向。推导（θ 自下垂点量起）：`θ̈ = −(g/l)·sinθ − (r/l)·cosθ·φ̈`，于是 `dE/dt = J·θ̇·θ̈ + mgl·sinθ·θ̇ = −m·l·r·θ̇·cosθ·φ̈`；要 `dE/dt > 0` 必须 `φ̈ = −u_E·sign(θ̇·cosθ)`。实机证据：旧版（符号反了 + 权限被限死）30 s / 19418 拍只到 E 峰值 0.00077 J（目标 2.100 J，0.04%），摆杆偏离垂位最大 0.034 rad，30 个采样行里 28 行卡在旧「抖速」分支、进「能量法」的 2 行立刻掉回。**标准 Furuta 能量法没有 |ω| 最小角速度要求**：旧版 `KickOmegaGateRadPerSec = 0.30` 的硬闸门会造成「抖速把摆幅顶到刚好 0.30 附近 → 能量法更弱 → 掉回抖速」的永久死循环，现已整个概念删除，能量项每拍都算。相位门改成**软符号** `x/√(x²+ε_ω²)`（`x = ω·cosθ`，`ε_ω = EnergySoftOmegaRadPerSec`，默认 0.10 rad/s）：只防 ω≈0 时把采样噪声放大成摆臂抖动，**不是闸门**，任何非零 ω 都会被同向放大。能量律在 ω≡0 处是数学鞍点（`dE/dt ∝ ω`），所以起摆最开始 `BootstrapSec`（默认 0.25 s）里叠一个确定方向的 `BootstrapAccelRadPerSec2`（默认 5.0 rad/s²）把对称打破，到点自动退出，不依赖摆杆固有频率、不需要相位。**不再按 |ω| 做增益调度**（旧 `OmegaScheduleStartRadPerSec` / `OmegaScheduleEndRadPerSec` / `GainFloor` 已删）——`ΔE` 本身把注入量收得很干净，再叠「|ω| 大就少推」等于在摆得最快、最需要权限时砍掉 80%；只保留近直立淡出（`ThetaFadeStartRad` / `ThetaFadeEndRad` / `ThetaFadeFloor`）。能量口径是 `E = 0.5·J_eq·ω² + mgl·(1−cosθ)`，目标 `E* = 2·mgl·(1+ε)`：**`J_eq` 与 `mgl` 必须成对给**（比值 = ω_n²，决定「能量到顶」对应多大的摆动速度），默认 `0.0122324 / 1.0` 对应等效摆长 0.12 m；旧版 1.0/1.0 会让判据在摆杆只有 ω≈2 rad/s（真实需要 2ω_n≈18 rad/s）时就认定到顶。默认 `ke_rad_per_s2_per_j = 60.0`、`amax_rad_per_s2 = 40.0`（旧值 `1.0` / `8.0` 让 `u_E` 上限只有 2.1 rad/s²，注入率凭空砍掉一个量级；`AMax` 与平衡律 `PidGains.AccMax = 60` 同量级，摆臂速度仍由 `omega_arm_max_rad_per_s = 20` 兜底）。**能量裕量 ε 必须极小且略负**：`E* = 2·mgl·(1+ε)` 是起摆与平衡的交接点，不是"多给点余量更保险"——切换判据要求摆杆在 `|ψ| ≤ θ_switch`（0.10 rad）处折返，对应能量带只有 `[mgl(1+cos0.10), 2mgl) = [1.995, 2.0) J`（mgl=1 时）。旧默认 `ε = +0.05` 让 E\* = 2.1 J **在分界线上方 5%**，摆杆到顶时必然还带着 `ω ≈ 4 rad/s`：`|ω| ≤ 3` 过不了、捕获门的模态幅值预算也过不了，**这时"起摆成功"在数学上不可能**——台架实测正是 E 冲到 2.094 J（E\* 的 99.7%）却以 9 rad/s 掠过顶端、永远抓不住。现默认 `ε = -0.002`（E\* = 1.996 J ⇒ 折返点 ψ ≈ 0.089 rad，给 θ_switch 留 10% 余量），合法区间 `[-0.02, 0.02]`。`timeout_ms` 默认 180000：本机耦合弱，从静止爬到捕获窗要 150 s 量级（实测 147 s 才到 E=1.86 J），旧的 30 s 必然误判失败；它只决定"多久算失败"，到点照常进 `Fault(SwingUpTimeout)`。往复泵默认**关**（`pump_amplitude_rad_per_s2 = 0`）：修正后的能量项是闭环、自找相位的，开环正弦只会跟它抢拍；要留作对照实验才打开。换一台摆除了调能量增益和加速度限幅，还必须按新等效摆长重标捕获门的 `capture_pendulum_rate_rad_per_s`（见「捕获门」一节的调参边界）。起摆中每 1 s 打一条 `[SWING] t=… 分支={起动|能量法|准备|回中} 能量E=… 目标=… 差=… φ̈能量=… φ̈泵=… ψ=… ω=… ω_est=… φ=…→…`——起摆超时就靠这条看能量项到底在不在算；`φ̈泵` 是**本拍实际施加**的泵加速度（泵关时 0.00），不是配置值（旧版恒打配置的 2.00，而泵根本没参与）。起动微扰固定 0.25 s；若到时能量仍未起来（<1%·E*）且 `|ω| < 0.5`，会继续微扰、最长 8×（2 s），一旦能量开始爬升立刻交还能量律。「准备」段 = `|ψ| ≤ 0.60 rad` 的**下降侧**（`ω < -0.05 rad/s`）且能量落在捕获窗 ±1.5%·2mgl 预窗口内：停泵、摆臂按速度伺服回起始位，目标速度随 `|ψ|/0.60` 收小，让过顶瞬间的 φ/φ̇ 落在提交条件内。上行侧不刹车——上行制动会把约 0.2 J 能量注回摆杆、把能量推出捕获窗。
- **能量整形（2026-11-20 实机）**：只注入不抽取会冲过 `E*` 后整圈转（实测 180 s 转 270 圈），所以在 `ΔE < −EnergyDeadbandRatio·E*` 时按 `ExtractGain·ΔE` 刹车，钳到 `−EnergyExtractRatio·AMax`。`ExtractGain` 与注入的 `Ke` **解耦**（默认 60）：台架为了让泵在整个爬升区间顶在 `AMax` 上把 `Ke` 取到 700，共用时 0.03 J 超调就产生 21 rad/s² 刹车、瞬间顶满抽取上限，实测 `energy_extract_ratio` 0.30 / 0.50 时 60 s 都攒不起能量。另加 τ=1 s 一阶低通扣除注入项直流分量，摆臂漂移从 40 s 17 圈降到 90 s 1.6 圈。`center_band_rad` 是漂移的第二道防线：`|φ|` 的预测刹车距离超过它就暂停注入、满 `AMax` 回中；出厂默认 **20 rad**（参数文件缺键 / 填 0 按 20 补齐，显式 3.6 保留），3.6 rad 在本台架太频繁（起摆 58 s），20 rad 实测 13 s。
- **切换判据（= 到位判据）= 粗筛 + 硬捕获门 + 提交臂速 / 摆杆角速度软上限 + 漏桶计数**：`|偏离直立|`、`|ω|` 两项是粗筛，每一拍还要过「不稳定模态幅值 + 摆臂两侧行程储备」的硬捕获门，并叠两条提交软上限 `|φ̇| ≤ 3.0 rad/s`、`|ω| ≤ 0.8 rad/s`；交棒条件可一句话概括为**硬捕获门 + `|φ̇| ≤ 3.0` + `|ω| ≤ 0.8`，净 20 拍即交棒**。慢通道 `switch_hold_cycles` 默认 60 净拍（且本拍仍须在提交条件内），快速通道 `capture_commit_hold_cycles` 默认 20 净拍；漏桶满足 +1、不满足 −2（`switch_hold_decay_per_cycle`），不是掉一拍就清零。count 视角：`|wrapPi(θ−π)| ≤ 0.10 rad ≈ 38 count`（2400 CPR）。**`theta_switch_rad` 必须不超过离线实测的平衡可恢复包线 `0.14 rad`**（`ψ0 ≥ 0.15 rad` 必失控），默认 `0.10 rad` 留约 29% 余量——门开得比能力大 = 明知会失控还进平衡。不满足绝不硬切——宁可继续摆或超时报故障，也不要猛甩摆臂。切换是 bumpless：PID 状态预置、摆臂基准从切换点起步再向 0 软滑。
- **顶部释放捕获（控制层能力，界面已无按钮）**：原「顶部释放捕获」按钮已删除，界面与 CLI 都不提供入口，桌面流程统一由「起摆」判据满足后自动切平衡。控制层仍保留 `PendulumEngine.ReleaseCapture()` 能力本身——摆臂目标钉在当前 `0x6064`（保持使能、不主动驱动），把摆杆扶到倒立 `|θ−180°| ≤ 8°` 并松手，检测到离开顶部（`|ω| ≥ 0.3 rad/s` 连续 3 ms，或跌出 30° 兜底）立刻切平衡 PD（1 kHz）。每次尝试记：释放 θ / ω、首次进入平衡窗口用时、保持时长、最大偏离、是否跌倒（`|θ−180°| > 30°`），写一行 `CAPTURE ...` 日志并在下次保存参数时落进 `captures`（最近 20 条）。等待 / 捕获期间掉使能、`0x603F≠0`、摆臂实际角越过软限位都立即安全停。
- **参数自测（原「系统辨识」，已并入起摆生命周期，界面没有独立按钮）**：从自由摆动（Enabled 态手动摆动）的 θ 过零估 `f_n`，从相邻同侧极值的对数衰减率估 `ζ`，从极值中点估静止角偏置；从历史捕获记录估可捕获释放 `|ω|` 上限；从起摆中实测的泵能量注入速率推泵幅，泵频取 `f_n`，`k_e` 初值取 `0.5·AMax/E*`。每次输出一行 `IDENTIFY ...`；样本不足写 `IDENTIFY insufficient_samples`，不编数。**两个自动应用点**：① 起摆开始时 `PendulumEngine.ApplyIdentifiedPumpFrequency()` 在样本充分且 `f_n` 落在 0.05~20 Hz 时用实测 `NaturalFreqHz` 覆盖泵频，并打一条「泵频 = 系统辨识实测 ω_n=… Hz（ζ=…，置信度 …，半周期样本 … 个）」，拿不到就明确打「使用默认 ω_n=… Hz（未辨识：原因）」；② 起摆切平衡时界面自动 `IdentifyNow()`，把推荐泵频 / 泵幅 / `k_e` 应用到起摆参数（`k_e` 只在用户没手改过时才应用）。推荐值同时回显在 PID 卡；点「保存参数」后一并写入参数文件；**原「系统辨识」按钮已删除，界面不提供手动触发入口**，样本不足时保持配置值并如实写日志，绝不编数。这条日志解决的是「参数文件里 `natural_freq_hz = 0`（从没辨识过）与辨识过但没人用，在日志里长得一样」的问题。
- **急停 / 停稳 / 故障之后必须重新起摆**。`Stopped` 与 `Fault` 里发 `balance` 一律拒绝（退出码 8）：急停后摆杆早已偏离直立，直接进平衡会猛甩摆臂。`balance` 只在起摆中（判据已满足时人工抢接）或平衡中（重置平衡参数组）有意义。
- **手动 `zero` 只用于重标定**：`zero pendulum` / `zero arm`（UI 对应「摆杆零点 (下垂 0°)」/「驱动臂零点」）是使能自动归零之外的**校正手段**，语义 = 把当前位置重新定成坐标 0（摆杆零点仍须落在自然下垂位、摆臂零点落在期望起始位）。`zero arm` **不再"设新 home"**——起始位置恒为 0，回中目标也恒为 0。**摆杆零点（`zero pendulum`）只在已连接 / 已停（未使能）有效**，按钮始终可点，但未连接、起摆 / 平衡 / 点动（`Enabled`）中点击会被拒并给中文原因；**摆臂零点可在点动中（`Enabled`）设置**——控制层在下一控制拍换零点基准，并把目标 / 参考 / 滑移 / 微分基准同步平移同一角度，`0x607A` 位置指令不跳变，起摆 / 平衡 / 整圈捕获中仍拒绝。改零点还要求 `左限位 < 零点 < 右限位`，越序直接拒写。**CLI `zero arm` / `zero pendulum` 落定后自动增量写盘**（回执带 `persisted`）；`zero pendulum` 同时把 360° 点按同一圈量平移到新 0° 点（回执 `pendulum360Rebased` / `calibrationNote`），清零前后角度连续、不会跳圈（角度按一圈取模，分支点落在直立点，不在垂位工作区）；UI 的采集按钮仍只改内存、要按「保存参数」，其「摆杆零点」采集不自动搬 360° 点，重标后仍需重采 360° 或改用 CLI `zero pendulum`。**不要用反复 `zero arm` 修漂移**：它只挪 φ=0、不搬软限位，反复在偏一侧的位置设零会让可用行程越跑越少；恢复用 `normalize`（零点 + 左右限位一起平移、跨度不变）或 `recenter`（回到行程中点后居中规整化），两者也会自动落盘。
- **摆杆每转计数是标定量，不是控制参数**：`CPR_PENDULUM` 按切片口径换算——**GC1602**（AB 正交）= 线数 × 4（AB 四倍频）× 传动比；**GC1502**（脉冲计数）= 每转脉冲 × 传动比，**不乘 4**（拿不准以运行时诊断为准）。**新口径：由「摆杆零点 (下垂 0°)」与「摆杆 360°」两点标定，一圈的量 = |360° − 0°|**（界面只显示结果，没有 CPR 输入框）。CLI 仍可用 `--pendulum-cpr <n>` 显式给值。**0 = 未标定就拒绝起摆，不猜**。参数文件把两点与派生值记进 `calibration`；CLI `--pendulum-cpr` / 入口参数始终优先。只在未连接 / 已连接 / 已停可改，运行中改会让 θ 在一拍内跳变，一律拒绝。
- **摆臂每转计数同样走标定链，不猜**：`CPR_ARM = 电机每转计数 × 减速比`，摆臂换算 `φ = (pos − φ_zero_count) × 2π / CPR_ARM`。给了 `--arm-cpr <n>` 就以它为准；不给则 CLI 启动先从参数文件 `calibration.arm_counts_per_rev` 恢复，文件也没有才交给控制层实读 **0x2102（开闭环细分设置 = 单圈脉冲数 P）× 减速比**（`--arm-gear`，默认 1.0）推导，推导不出就拒绝运动并报差异。**0x608F 只在有该对象的机型做交叉校验**（EC1 全系没有）。`--arm-cpr` 同样是机器量；GUI 参数文件在 `calibration.arm_counts_per_rev` 里持久化「当前假设 10000 / 现场实测值」用于界面换算与恢复，CLI 启动在未给 `--arm-cpr` 时也读这一项（运行时 0x2102 实读仍是权威，文件值只在实读不到时兜底）。只在未连接 / 已连接 / 已停可改（运行中改会让 φ 在一拍内跳变，一律拒绝）。**未标定时遥测不编假值**：`CPR_ARM = 0` 时 `phi_rad` / `phi_dot_rad_s` 两列如实写 `nan`（旧版拿 `cprArm = 1.0` 兜底，把 `arm_pos_count = −8334` 算成 `phi_rad = −52364.07`，真值 −5.235 rad），并打一条「摆臂未标定（CPR_ARM = 0）…使能 / 起摆时会实读 0x2102 定标」的诊断；标定值变化的那一拍重置 φ 的微分基准，避免跳变把 φ̇ 打飞。
- **`0x606C` 实际速度的单位是 Pulse/s，不是 rpm；而且它只给幅值**：手册 4.1.3 与 V1.0.1 修订历史写 rpm、5.3 表写 Pulse/s，两处互相矛盾，**实机实测站得住的是 Pulse/s**。台架 30 s 起摆的 23418 拍遥测：`0x606C` 原始值只有 0 / 1000 / 2000 / 3000（量化步长 1000），**无一为负**（同期摆臂反复换向）⇒ 这台驱动器回的是 |速度|；峰值拍 `|φ̇| = 1.655 rad/s` 对应 `0x606C = 2000`，按 `Pulse/s ÷ CPR_ARM(10000) × 2π` 得 **1.257 rad/s**（同为 0.6 rad/s 量级），按 rpm 换算得 **209.4 rad/s**——比 `Ω_arm_max = 20 rad/s` 大 10 倍、比实测大 126 倍，物理上不可能。判据式复核：把新换算的 `|φ̇|` 积分与 `0x6064` 的位置路径比较，`∫|φ̇|dt = 18.554 rad` vs `Σ|Δφ| = 18.627 rad`，**比值 0.9961**。换算只在 `ControlMath.ArmRadPerSecFromDrivePulsePerSec` 一处做，分母 = **每转位置单位**（有 `0x608F` / `0x6091` 的机型按 OD 实读合成 `0x608F:01 × 0x6091:01 / 0x6091:02`；EC1 这类没有这两个对象的按 `0x2102` 细分 × 减速比），**不写任何经验系数**。`0x6064` / `0x606B` / `0x6081` 与它同口径（都是 Pulse）。低速段要注意量化：静止时它会停在 0 或 1000（0.628 rad/s）两档，不能当零速判据。遥测里 `ArmVelocityFromDriveRadPerSec` 是换算值（幅值、无符号）、`ArmVelocityPulsePerSec` 是原始值（CSV 两列都有）——「速度积分 vs `0x6064` 增量」就是这一路的现场复核方法。

## 捕获门（起摆 → 平衡的交接判据）

只看「离直立足够近」会在失稳区放行。交棒分两层：`theta_switch_rad` / `omega_switch_rad_per_s` / `phi_switch_rad` 是**粗筛**；每一拍还要过**硬捕获门**（不稳定模态 + 摆臂行程预算的联合判据），再叠两条**提交软上限**：`|φ̇| ≤ capture_commit_arm_rate_rad_per_s`（默认 **3.0 rad/s**）和 `|ω| ≤ capture_commit_omega_rad_per_s`（默认 **0.8 rad/s**）。交棒语义收敛成一句：**硬捕获门 + `|φ̇| ≤ 3.0` + `|ω| ≤ 0.8`，净 20 拍即交棒**。

`|φ̇| ≤ 3.0` 的理由（工程师视角）：摆臂已经贴近行程侧、还以最大速度继续朝那侧跑时，它已经没有剩余行程去吸收摆杆了。实测首次失败出现在 `|φ̇| = 4.0 rad/s`，所以软上限取 3.0，留 25% 裕量；硬门自身的 `capture_arm_rate_limit_rad_per_s = 4.0` 仍然保留。

`|ω| ≤ 0.8` 的理由（2026-11-20 台架实测）：一次交棒发生在 `ψ=−0.068 rad`、`ω=+1.10 rad/s`，因为摆角很小，硬门的模态幅值只有约 0.031，远低于 0.16，所以**硬门放行了**；但平衡接管后 **0.31 s 就失控**，摆杆冲到 1.05 rad。这是一类「摆角很小、但角速度很大」的穿越状态——硬门对它是盲的，必须单独限制。`capture_commit_omega_rad_per_s` 默认 0.8，范围 (0,10]，运行期自动钳到粗筛 `omega_switch_rad_per_s = 3.0` 以内。

**提交模态幅值仍然不设旋钮**：正确耦合符号下硬捕获门的 `|u| ≤ 0.16` 已经覆盖模态幅值；旧的提交模态幅值参数已删除，不要按旧文档找。

计数用**漏桶**，不是「掉一拍就清零」：满足一拍 +1，不满足 −`switch_hold_decay_per_cycle`（默认 2），计满目标净拍数才交棒。两条通道任一满足即可：

- **慢通道** `switch_hold_cycles`（默认 **60 净拍**）：只在硬捕获门满足时 +1；计满后还要求**本拍仍在提交条件内（`|φ̇| ≤ 3.0` 且 `|ω| ≤ 0.8`）**才交棒。`switch_hold_cycles` 现在是「净拍数」语义，不是严格连续拍数。
- **快速通道** `capture_commit_hold_cycles`（默认 **20 净拍**）：只在「硬门 + 臂速软上限 + 摆杆角速度软上限」都满足时 +1；掠顶窗口只有约 80 ms（40 拍 @ 2 ms），慢通道的 60 拍在物理上覆盖不了，短窗交棒靠这一条。

台架上的预期现象：`[SWING]` 的「分支」在**下降侧**、`|ψ| ≤ 0.60` 时出现 `准备`；过顶前摆臂速度被压到 `|φ̇| ≤ 3.0 rad/s`、摆杆角速度在 `|ω| ≤ 0.8 rad/s`；`门倒计时` 在一两个掠顶周期内到 0 并切平衡。如果倒计时长期停在 1，说明慢通道已满但本拍臂速 / 摆杆角速度没进软上限，先把摆臂收回起始位 / 查预捕获回中，不要去放宽硬捕获门。

### 预捕获回中（日志分支「准备」）

条件是同时满足：`|ψ| ≤ capture_prepare_approach_rad`（默认 0.60）、**只在下降侧**（`ω < -0.05 rad/s`）、能量落在捕获窗 `[mgl(1+cosθ_switch), 2mgl+½J(u_max·ω_n)²]` 再向两侧各放 `capture_prepare_energy_margin_ratio·2mgl` 的预窗口内、且当前不在软中心带回中。满足后停能量泵与往复泵，摆臂按速度伺服回起始位置；回中目标速度按 `|ψ|/capture_prepare_approach_rad` 线性收小（默认满速 3 rad/s，`|ψ|≈0.10` 时约 0.5 rad/s），过顶前把臂速压到 3.0 rad/s 以内。

**上行侧不刹车**：上行侧制动会把约 0.2 J（E* 的 10%）能量注回摆杆，直接把能量推出捕获窗；下落侧制动是抽取，能量由中段能量泵补回。所以「准备」只在下降侧出现，看到它在上升侧出现属于参数或状态异常。

### 提交条件（硬门 + 臂速软上限）

真正交棒只需满足：

```text
硬捕获门 ready 成立
且 |φ̇| ≤ capture_commit_arm_rate_rad_per_s   // 默认 3.0 rad/s，硬门臂速 4.0 的 75%
且 |ω| ≤ capture_commit_omega_rad_per_s      // 默认 0.8 rad/s，运行期钳到 omega_switch_rad_per_s 以内
```

**为什么是 3.0**：摆臂已经贴近行程侧、还以最大速度继续朝那侧跑时，它已经没有余量去吸收摆杆了。实测首次失败出现在 `|φ̇| = 4.0 rad/s`，所以软上限取 3.0，留 25% 裕量。`capture_commit_arm_rate_rad_per_s` 必须 ≤ 硬门 `capture_arm_rate_limit_rad_per_s`；保存 / CLI 主动改越界会拒收，参数文件载入越界会按硬门收紧并写 warning。

**没有提交模态幅值 / 提交摆杆角速度**：正确耦合符号下硬捕获门的 `|u| ≤ 0.16` 已经覆盖模态幅值；`omega_switch_rad_per_s = 3.0` 与提交摆杆角速度本就是同一个数。这两个旋钮已删除，不要按旧文档找。

### 判据式

```text
ψ   = wrapPi(θ − π)                 // 偏离直立角
ω   = 逐拍 ω 估计（40 ms 窗**二次拟合、取窗口末端斜率**，不是 2 ms 差分；旧线性拟合的质心斜率有半窗滞后）
ω_n = capture_pendulum_rate_rad_per_s
u   = ψ + ω/ω_n                     // 线性化 ψ̈=(g/l)ψ+(r/l)φ̈ 的不稳定模态

avail    = u ≥ 0 ? (φ − φ_min) : (φ_max − φ)      // 摆臂朝发力方向还剩多少行程
room_low = φ − φ_min ; room_high = φ_max − φ
phi_cap  = phi_switch_rad · max(1, (φ_max−φ_min)/2 / 1.8)   // 标定台架半行程 1.8 rad
adverse  = (u > 0 且 φ̇ < 0) 或 (u < 0 且 φ̇ > 0)   // 臂已在往反方向跑，要先刹住
required = capture_stroke_per_mode_rad · |u|
         + (adverse ? capture_adverse_rate_stroke_sec · |φ̇| : 0)
         + capture_stroke_margin_rad

硬门 ready = |ψ| ≤ theta_switch_rad
   且 |ω_est| ≤ omega_switch_rad_per_s
   且 |u| ≤ capture_mode_amplitude_max_rad
   且 |φ̇| ≤ capture_arm_rate_limit_rad_per_s
   且 |φ| ≤ phi_cap
   且 required ≤ avail
   且 room_low ≥ phi_switch_rad 且 room_high ≥ phi_switch_rad
```

`u` 为正是「摆杆偏正侧、且正在 / 将要往正走」，此时摆臂必须往负方向加速（朝 `φ_min`）把它拉回来，所以 `avail` 取 `φ − φ_min`；`u` 为负则反之。`phi_cap` 是 2026-11-20 的修正：0.6 rad 是在 φ∈[±1.8] rad 的模型 H 台架上标定的绝对角，本机半行程≈13.7 rad，按比例放大到≈4.6 rad——否则「摆杆到顶时摆臂离起始位 1 rad、离限位还有 9 rad」这种安全状态会被误拒。小行程台架上 `max(1,…)` 恒为 1，判据与旧版一致。

**硬门 `ready` 只负责漏桶计数，不直接交棒**：慢通道 `switch_hold_cycles` 在 `ready` 时 +1，但计满后还必须本拍满足 `|φ̇| ≤ capture_commit_arm_rate_rad_per_s` 与 `|ω| ≤ capture_commit_omega_rad_per_s`；快速通道在「硬门 + 两条软上限」都满足时 +1。两通道都按漏桶扣减（默认 −2/拍）。`dashboard` 的「切换判据」行与 `[SWING]` 的 `门倒计时`（`status --json` 的 `SwitchCountdown` 同源）取两条通道剩余拍数的较小值；慢通道已满但臂速 / 摆杆角速度没进 3.0 / 0.8 时显示 1，提示还差软上限这一下，不要误读成「门永远不开」。

### 为什么是这几条，而不是能量判据

用能量判据会在相位上失真：ψ=0.10、ω=0 与 ψ=0.10、ω=+0.5 的摆杆能量只差 `0.5·J_eq·0.5² = 0.125·J_eq`（约为 `mgl` 的 0.15%，按 `mgl/J_eq = ω_n² = 81.75` 折算），但前者收敛、后者必失控——能量只回答「够不够到顶」，分不出「此刻在往哪走」。`u = ψ + ω/ω_n` 把位置和速度放进同一个不稳定模态坐标，才能分出这个相位差。

三条阈值各自判也不行：可恢复集在 (ψ, ω, φ) 里不是矩形。离线细扫里 ψ=0.08、ω=+0.5 在 φ=0 收敛、在 φ=−0.6 失控；同样 `|ψ|=0.10` 时，ω=+0.5 的 `u=0.155` 落在边界外，ω=−2 的 `u=−0.121` 仍在边界内。所以判据把「摆杆现在有多难拉住」（`|u|`）和「摆臂两侧还剩多少行程」（room_low / room_high）放进同一个预算，再叠 `|u|` 与臂速两条硬上限。

**硬门之上保留两条软上限**：① 臂速 `|φ̇| ≤ 3.0`——摆臂已经贴近行程侧、还以最大速度继续朝那侧跑时，它已经没有余量吸收摆杆；实测首次失败出现在 `|φ̇| = 4.0 rad/s`，取 3.0（硬门 4.0 的 75%，留 25% 裕量）。② 摆杆角速度 `|ω| ≤ 0.8`——台架实测一次交棒在 `ψ=−0.068、ω=+1.10`，摆角很小导致硬门模态幅值只有约 0.031、远低于 0.16，**硬门放行了**，但平衡接管 0.31 s 后就失控（摆杆冲到 1.05 rad）；这是「摆角很小、角速度很大」的穿越状态，硬门对它是盲的，必须单独限制。提交模态幅值仍不设旋钮：硬门的 `|u| ≤ 0.16` 已覆盖模态幅值。

### 调参边界（改之前先看）

- **`theta_switch_rad` 必须 ≤ 0.14 rad**（离线细扫的平衡可恢复包线；`ψ0 ≥ 0.15 rad` 必失控）。`IsValid` 直接拒收 > 0.14 的值（界面 / CLI 主动设参数时整组拒绝）；旧参数文件里的 0.28 在**读回**时走逐字段修复——只把 `theta_switch_rad` 换回 0.10 并写进 `load-config` 的 warning，其余字段照常生效，不再让整份文件校验不过。默认 0.10 rad 留约 29% 余量。
- **`|u|` 上限与 `capture_stroke_per_mode_rad` 是绑定的**：最坏组合 `capture_stroke_per_mode_rad × capture_mode_amplitude_max_rad + capture_stroke_margin_rad` 必须 **< 3.0 rad**（软限位全行程 3.6 rad），否则判据永远等不到满足、起摆只会超时。默认组合 = 12.3×0.16+0.05 = 2.02 rad。**改了内环增益或摆臂能力，必须重新离线标定这两个数**，不要凭感觉把门开大。
- **默认整组针对 l = 0.12 m 的摆**：`capture_pendulum_rate_rad_per_s` = √(g/l) = √(9.81/0.12) ≈ 9.0416（台架实测自由摆动 1.422 Hz ⇒ 8.93 rad/s，差 1.2%，量级一致）。换摆杆必须按新等效摆长重标这一项，**并且**把 `jeq_kg_m2` / `mgl_n_m` 按 `J_eq = m·l²`、`mgl = m·g·l` 成对改，让 `√(mgl/J_eq)` 与它相等：能量法对整体尺度不敏感（Δ 同乘一个系数，被 `Ke` 吸收），但对**比值**极其敏感，比值就是 ω_n。出厂 `J_eq = 0.0122324 kg·m²`、`mgl = 1.0 N·m`（等效点质量 ≈0.85 kg 落在 0.12 m 处）就是按这条配的；旧版 1.0/1.0 隐含 ω_n = 1 rad/s（等效摆长 9.81 m），会把目标能量 `E* = 2·mgl` 判在摆杆只有 ω≈2 rad/s 时"已到顶"，能量泵随即反向抽能——读到这种旧值会被 `load-config` 换成上面这一对并在提示里写明。
- **耦合比 `limits.radius_ratio`（r/l）出厂 0 = 未标定，不猜**：能量法本身不读它（方向律与 r 无关），但它决定**注入的绝对量级**（每周期 `ΔE = 4·(m·l·r)·u_E·G(θ)`，`m·l·r = (r/l)·mgl/g`）。起摆日志会打「耦合 r/l=…（来源：参数文件 limits.radius_ratio，机构实测值）⇒ m·l·r=… ⇒ u_E 顶到 AMax 时每半周期最多注入 ΔE≈… J」；未标定时如实打「r/l 未标定」并给出标定步骤。**标定只能靠直接量或受迫响应扫频，不能靠回归 θ̈ 对 φ̈**：摆臂编码器 2400 count/转，量化步长 2.6e-3 rad，4 ms 二次差分的噪声约 116 rad/s²，而真实 φ̈ 只有 20~40 rad/s²，最小二乘斜率会被压小 1~2 个数量级——历史上「拟合值 0.015~0.021」与「几何估计 ~0.4」差 20 倍正是这个衰减造成的（0.4 压 20~30 倍就是 0.015 量级），**两者谁对不能靠拟合判定**。受迫响应扫频的做法与频点、幅度、锁相要求见 `内部文档/设计/FurutaPendulum/01-控制层契约.md` §4.1.2。 **摆臂"转那么点、甩不起来"的三个数（2026-11-16 实测）**：① 软限位**只认绝对 counts**（`左 < 零点 < 右`，无角度 / 行程上限；旧版 ±5.5 rad 与 3π 判据已删除）——依据是上一轮遥测实测 φ=−5.14 rad（转过 295°）无损伤；现场按实际左右边界采集即可。② 峰值角速度 `OmegaArmMaxRadPerSec` 出厂 **20 rad/s**，算式 `v_peak = A·2πf`（A=半行程、f=摆杆 1.44 Hz）：A=1.8 rad 需要 16.3 rad/s，旧默认 12 连 ±103° 的正弦扫程都跑不满（实测峰值 9.2~9.6 rad/s 已贴近旧限速）。③ **回中项不许抢能量项的加速度预算**：旧 `KPhi=6 / KPhiDot=1.5` 在 φ̇=9.6 rad/s 时贡献 −14.4 rad/s²，占 AMax 的 36%~72%，把一次泵动的摆臂峰峰值压到 0.72~0.85 rad（软限位 3.6 rad）——这就是"就转那么点距离"的直接原因。现在回中项单独钳到 `CenterAuthRatio·AMax`（默认 20%），刚度降到 `KPhi=3.0 / KPhiDot=0.8`，能量项永远至少剩 80%。**待上机**：驱动器 0x607D 位置限位 / 0x6080 速度限幅必须同步复核（见 `05-EC1-手册要点.md`）。
- **`capture_mode_amplitude_max_rad` 的标定硬边界是 0.163 rad**：`IsValid` 形式上接受至 0.20，但离线细扫里 `|u| ≥ 0.17` 的格点无一收敛，默认 0.16 已贴近边界；`capture_arm_rate_limit_rad_per_s` 同理，`|u|` 很小而 `|φ̇| = 6 rad/s` 的样本必然失控，默认 4.0 不要为了「更容易切」往上开。
- **提交臂速 / 提交摆杆角速度软上限只许收紧、不许放宽**：`capture_commit_arm_rate_rad_per_s` 默认 3.0，合法 (0, 6.0]，且必须 ≤ 硬门 `capture_arm_rate_limit_rad_per_s`（默认 4.0）；`capture_commit_omega_rad_per_s` 默认 0.8，合法 (0, 10.0]，运行期自动钳到 `omega_switch_rad_per_s`（3.0）以内。越界保存会被拒收，参数文件载入会按对应硬门收紧并写 warning。摆臂贴近行程侧还在全速朝那侧跑时没有余量吸收摆杆；实测首次失败在 4.0，3.0 留 25% 裕量。摆杆「摆角很小、角速度很大」的穿越能骗过硬门（实测 `ψ=−0.068、ω=+1.10` 时模态幅值仅约 0.031，0.31 s 后仍失控），所以单独保留 `|ω| ≤ 0.8`。**提交模态幅值参数已删除**：硬门已覆盖 `|u| ≤ 0.16`，不要按旧文档找。
- **预捕获回中窗口别贪大**：`capture_prepare_approach_rad` 默认 0.60，合法 (0, 1.5]；再大会在整个下落半周期停泵，能量爬不上去。`capture_prepare_energy_margin_ratio` 默认 0.015，合法 (0, 0.1]；再大等于长期停泵。
- **漏桶衰减 `switch_hold_decay_per_cycle` 默认 2**（合法 [0,10]，0 = 未配置按 2）。`k=2` 要求可捕获占空比 > 2/3；调大只是让边界抖动更容易被容忍，不会提高可恢复包线。`capture_commit_hold_cycles` 默认 20（合法 [1,200]），再大等于退回慢通道，掠顶窗口内来不及提交。
其它校验边界（`IsValid`）：`capture_mode_amplitude_max_rad` ∈ (0, 0.20]、`capture_stroke_per_mode_rad` ∈ [1, 40]、`capture_stroke_margin_rad` ∈ (0, 0.5]、`capture_adverse_rate_stroke_sec` ∈ (0, 5]、`capture_arm_rate_limit_rad_per_s` ∈ [0.5, 20]、`capture_pendulum_rate_rad_per_s` ∈ [1, 60]；保留六项的范围见上节参数表。
- 硬门 6 个键与预捕获 / 提交臂速 / 提交角速度 / 漏桶 6 个键都在参数文件 `swingup` 段；旧文件缺键按内置默认补齐。这六项目前**没有 UI 输入框**，改法 = 参数文件或 CLI `setswingup --prepare-approach` / `--prepare-energy-margin` / `--commit-arm-rate` / `--commit-omega` / `--commit-hold-cycles` / `--hold-decay`（起摆中锁定；Connected / Balancing / Fault 拒绝）。旧的提交模态幅值参数已删除，不再存在。改完用 `load-config`（仅 `Disconnected / Connected / Stopped`）或重启 GUI 自动载入。生效值看 `status` / `dashboard` 的「捕获交棒」行和 `load-config` 的回显；`status` 的「到位判据」与 `dashboard` 的「切换判据」行也显示两条软上限与双通道倒计时。

### 验证边界（离线数值；真机已跑通起摆，平衡未解决）

以下几条是**离线数值仿真 / 台架状态对照**，不是新起摆逻辑的完整真机验证：模型 H（`0x6064` 镜像指令 + 100 Hz 伺服）、线性化摆、**l = 0.12 m 是假设值**、2 kHz、φ∈[−1.8, 1.8] rad、臂速上限 6 rad/s、初始 ψ̇=0。**2026-11-20 真机已跑通起摆并进入捕获门**（起摆 13 s 量级），但平衡接管后约 0.26 s 发散（见「已知问题」），所以下面的包线仍只作离线参考，现场首次使用按上节调参边界保守起步并全程盯 `status`。

- 可恢复包线：ψ0 ≤ 0.14 rad 全部收敛，ψ0 ≥ 0.15 rad 全部失控（补测 0.145 rad 收敛）。
- 315 格点：放行 138 个，全部真收敛，**假阳性 0**；细扫 1872 点：放行 1132 个，**假阳性 0**；负 ψ 镜像 315 点完全对称。
- 边界样本：`(ψ=0.08, ω=0.72, φ=+0.3)` → `u=0.1596`，放行且收敛；`ω=0.74` → `u=0.1618`，拒绝且确实失控。
- **当前判据的台架现象对照（2026-11-20 捕获交棒重构）**：`[SWING]` 的「分支」应在**下降侧**、`|ψ| ≤ 0.60 rad` 时出现 `准备`；过顶前 `φ̇` 应被压到 `|φ̇| ≤ 3.0 rad/s`，交棒前 `|ω|` 应在 0.8 rad/s 以内；`门倒计时` 应在一两个掠顶周期内到 0 并切平衡。若 `准备` 不出现，先查 `capture_prepare_approach_rad` / 能量预窗口 / `ω` 是否在下降侧；若倒计时长期停在 1，查硬捕获门、`|φ̇| ≤ 3.0` 与 `|ω| ≤ 0.8`（先看预捕获回中是否把臂速压下来），不要先放宽硬门。
- **2026-11-20 起摆可靠性回归（离线，未上真机；旧版「连续 60 拍」逻辑）**：模型 H 理想镜随摆臂、同一组台架参数、20 组初始条件（ψ0 = 0…π 每 π/9、ω0 = ±1 rad/s）。**改前 2/20**，且两个成功都是 `ψ0=0`（初始就在直立）的退化样本；真正从底部摆起的 18 组**全部 60 s 超时**（18×GATE：能量到约 2.0 J，但捕获门从未连续满足 60 拍）。**改后 20/20**，非退化 18 组捕获耗时 5.2~55.8 s（均值 19.6 s），失败阶段 0；同一起点（下垂 + 微小扰动）8 组改后 8/8（均值 13.1 s）。把摆臂换成力矩受限二阶伺服（**假定参数，不是台架实测**）后，成功率随假定力矩/惯量在 5%~90% 之间变化——剩余不确定性在摆臂真实力矩-转速能力，现场需用 `[SWING] 泵执行器包线` 那行核对。

### 机构几何 r/l（2026-11-20 主动标定实测 0.24）

捕获门与平衡律都建立在同一个线性化模型上：`ψ̈ = (g/l)·ψ + (r/l)·φ̈`。其中 **l = 摆杆重心到转轴的距离**、**r = 臂轴到摆轴的距离（曲柄半径）**。仓库里**没有这台机构的零件尺寸来源**（ESI 不含几何量、手册没有机构图），但参数文件现在有 `limits.radius_ratio`；控制层把它用于捕获门的接管模态计算，平衡启动时再按历史判据 `(r/l)·Ka > g/l` 打一条对照日志（`Ka` 已不参与平衡，见「2026-11-20 实机结论」）。

- **l ≈ 0.12 m 有实测背书**：由自由摆动的自然频率反推 `l = g/(2πf_n)²`，台架实测 `f_n = 1.422 Hz` → `l ≈ 0.123 m`，与 `capture_pendulum_rate_rad_per_s = 9.0416`（对应 0.12 m）一致。
- **`r/l ≈ 0.015~0.021` 是旧方法的拟合结果（已被 2026-11-20 的主动标定取代，保留作历史）**：用共振点附近的响应比 `B_θ/A_φ` 与阻尼比按 `r/l ≈ 2ζ·B/A` 反推得到。它是**下限估计**——小振幅下库仑摩擦占主导（实测阻尼比随摆幅下降：18° 摆幅 ζ=0.036、62° 摆幅 ζ=0.0079，正是摩擦特征），线性黏性阻尼模型会把等效阻尼低估，`r/l` 随之下偏；再加上摆臂编码器量化噪声，斜率会被压小 1~2 个数量级。
- **同类 Furuta 机构常见 `r/l` 在 0.1~0.5**（臂长与摆长同量级）。若按「臂半径 0.05 m / 摆长 0.12 m」粗算 `r/l` 约 0.42；2026-11-20 主动标定实测 **0.24**（对应臂半径约 0.03 m），落在这个区间内。`r = 0.05 m` 这一项**没有任何图纸或测量来源**，只是早前给稳定性阈值 `Ka > g/l = 196.2` 配的说明文字（该阈值里的 196.2 对应等效摆长 0.05 m；实测 0.12 m 给出 `g/l = 81.75`，出厂 `Ka = 500` 同时高于两者，所以现行默认不受影响）。旧注释曾把 0.05 m 写成「摆臂半径 r」，与耦合比里的 `r` 撞名，已更正为 `g/l`；不要再拿 0.05 当 r 的测量值。
- **结论**：`r/l` **必须按实际机构标定**，**不要照抄 0.015~0.021 去改任何参数**，也不要为了让这个比值"看起来正常"去改 `Ka` / 捕获门默认值。现在有主动标定命令：`calibrate-radius`（摆杆下垂静止时给四相 ±加速度脉冲，用窗口内实测 φ̈ / θ̈ 二次拟合反推；离线数学验证真值 0.24 时估计落在 **0.228~0.249**）。2026-11-20 台架实测 **`r/l = 0.24`**（`Ka=900` → `(r/l)·Ka = 216 > g/l = 81.8`，2.6 倍结构裕量）。它同时是判断「能量法在这台机构上够不够力」的关键量：`r/l` 越小，同样的摆臂加速度注入给摆杆的能量越少，起摆需要的时间越长。
- **旧的 `0.015~0.021` 是量化噪声造成的下限估计，不是尺寸**：4 ms 二次差分的噪声约 116 rad/s²，而真实 φ̈ 只有 20~40 rad/s²，最小二乘斜率被压小 1~2 个数量级；新的 40 ms 窗口二次拟合法把噪声压到 0.25 rad/s² 量级，才给出 0.24 这个可用的实测值。
- **当前状态（2026-11-20）：已用主动标定实测 `r/l = 0.24`**。旧的拟合值 0.015~0.021 与几何估计 ~0.4 差 20 倍，前者已由量化噪声解释、后者没有任何图纸或测量来源；0.24 落在同类机构常见的 0.1~0.5 内。能量注入率正比于 `m·l·r`（`dE/dt = −m·l·r·θ̇·cosθ·φ̈`）；**起摆时间仍取决于真实 `r/l` 与摩擦，必须用 `calibrate-radius` 实测值下结论**，不要照抄历史拟合值。历史结构判据 `(r/l)·Ka > g/l` 现在可以用实测值对照启动日志：`0.24×900=216 > 81.8`（`Ka` 已不参与平衡，这条只作参考）。

## 性能与实时性

500 µs 周期由 **DarraRT 内核驱动的节拍门铃**保证，控制律在**用户态**逐拍执行；用户态不抬优先级、不做实时补拍。UI 的「总线与采样」卡给实测 `PDO 周期计数` / `采样时刻` / `WKC 实际·期望`（不是只报设定值）；CLI 的 `status` / `watch` 同样给实测值，判断「周期真不真」看实测不看配置。

**单拍过程数据抖动不立刻停机**：某一拍没合并到帧时，控制律沿用上一拍**已确认**的过程数据继续跑（`status` 的 PDO 行显示 `STALE 连续 / 累计`，周期日志行带 `stale=N`），连续 **20 拍（默认 500 µs 周期下约 10 ms）**仍取不到有效过程数据才按 `PdoFrameLoss` 切安全态。从站真掉线（`IsLost` / 掉出 OP）仍按原规则立即停，不走这条去抖；`expected_wkc` / `actual_wkc` 照常如实上报，不因去抖改动。

**周期下限是 500 µs（2026-11-20 实机）**：250 µs（4 kHz）时 `InputsSliceMapping` 抛「PDO 输入映射不可用」，内核日志报「同一周期内重复通知同一个 PDO 输入缓冲区」。500 µs 下关 DC 使能耗时 **87 ms**（开 DC 166 ms）。周期由 DENI 决定，改周期必须回 GUI 重新导出 DENI。

### 退出码

| 码 | 含义 | 典型场景 |
|---|---|---|
| 0 | 成功 | 命令完成、`quit` 干净收尾、到点自动 `stop` |
| 1 | 一般运行失败 | 意外异常、周期回调抛异常、单命令执行超时（`--timeout` 到点，`swingup` 除外归 5） |
| 2 | 参数 / 用法错误 | 未知旗标、数值越界、参数校验不过 |
| 3 | SDK 激活失败 | SDK 授权 / 凭据 / 激活失败 |
| 4 | 连接失败 | 网卡不唯一、DENI 对不上、Build 超时、身份预检不过 |
| 5 | 总线 / 反馈故障 | 掉站、WKC 不符、PDO 连续 20 拍不可用（`PdoFrameLoss`）、编码器冻结、起摆超时 |
| 6 | 配置 / 参数错误 | 参数文件缺字段、DENI 不存在 |
| 7 | **安全联锁触发** | θ 超限、平衡丢失、跟随误差超限、硬接线急停 / STO |
| 8 | 状态机拒绝 | 未连接就使能、`Stopped` 直接 `balance` |
| 9 | 设备 / 驱动故障 | 驱动未运行、使能丢失、驱动报错、收尾超时 |
| 10 | 需要确认 | 危险命令缺 `--yes` 且非交互 |
| 130 | 取消 | Ctrl+C（128+2） |

`$LASTEXITCODE` 7 = 安全联锁把机器停了；5 = 总线/反馈不可信；9 = 驱动设备侧出事；8 = 状态机不接受这条命令。脚本按这张表判，不要按「有没有打印 ok」判。

### Ctrl+C 与 `--yes`

- **Ctrl+C = 急停，不是退出。** 一次性 / 序列 / 脚本里按 Ctrl+C：立即急停（插队到命令队列最前）→ 安全收尾 → 退出码 130。REPL 里第一次只急停不退出，5 秒内再按一次（或 `quit`）才收尾退出。急停后状态是 `Fault` + 急停锁存，必须 `fault-reset`（= `Stop()`）清锁存才能再动。
- 软件急停只是把 `0x6040` 清零，**不是安全回路**，不替代硬接线急停 / STO / 限位。
- **`--yes` 只拦 `enable` / `swingup` / `balance` / `zero` 四条。** 非交互形态（一次性 / 序列 / 脚本）跑这四条必须带 `--yes`，否则退出码 10。REPL 里有人在场会打一行 `[y/N]` 确认；启动带了 `--yes` 就全程不问。安全方向永不设门槛。

### 日志与结果文件

诊断日志（GUI 与 CLI **共用同一个根、同一套命名、同一种行格式**）统一落 `%AppData%\DarraPLC\logs\furuta_<yyyyMMdd>.log`，行格式 `[yyyy-MM-dd HH:mm:ss.fff] [kind] 正文`，`kind` 是记录类别（`ui` / `diagnostic` / `ack` / `error` / `event` 等）。`log-path` 打当前日志绝对路径（并列出历史遗留目录）；`--log` / `--result` 可改落点。**历史遗留（只读）**：旧 CLI 路径 `%LocalAppData%\DarraEtherCAT\FurutaPendulum\logs\` 仅用于查历史日志，新日志不再写那里，也不删除旧目录。结构化结果 `last_result.json` 仍落 `%LocalAppData%\DarraEtherCAT\FurutaPendulum\`（每次退出覆写，脚本可取）。周期回调里禁止日志，控制台写不动就丢行计数，绝不把 500 µs 周期拖长。

## 用 CLI 实时整定 PID

`tune` 只看不改，`setpid` 改完当拍热生效（generation 双缓冲，下个周期拍首顶换）。**平衡环由固定的 5 状态状态反馈驱动：外环 `Ka / Kad / Kai` 已不参与平衡**。`setpid --ka / --kad / --kai` 仍可用（兼容既有脚本），写入只进参数文件与界面显示，调它们不会改变平衡；按旧规则，`--ka` 低于结构下界仍会被拒绝，这条也是历史兼容校验。现在真正还能调的是内环 φ（`--kp-phi / --ki-phi / --kd-phi`、`--td-lp-ms` 等）与内环输出限幅。内环单位：Kpφ `rad/rad`、Kiφ `1/s`、Kdφ `s`，输出 `rad`。起摆泵加速度幅仍在 `setswingup --pump-amp`，单位 **rad/s²** 不变。

### 走查流程

```
furuta> enable
furuta> swingup --timeout-ms 20000          # 起摆中看 φ 环往复是否对称
```

### 相对调整语法

`setpid` 的外环增益旗标（`--ka --kad --kai`；旧 `--kp --ki --kd` 仍接受但控制律不读取）是**历史参数**：仍受旧结构校验、仍会写进参数文件，但不参与平衡。内环（`--kp-phi --ki-phi --kd-phi`）是当前生效项。两类旗标的取值都带符号 = 相对现值增减，不带符号 = 绝对设置；`--ka=-50` 与 `--ka -50` 同义：

| 写法 | 含义 |
|---|---|
| `setpid --ka 600` | 绝对设置 `Ka = 600`（历史参数，不影响平衡） |
| `setpid --ka +100` | 相对增加：`Ka = 500 + 100 = 600`（同样不影响平衡） |
| `setpid --kad -5` / `setpid --kad=-5` | 相对减少：`Kad = 55 − 5 = 50`（同样不影响平衡） |
| `setpid --kp-phi +0.05` | 相对增加内环比例增益（**当前生效**） |

`td-lp-ms` / `out-min` / `out-max` / `out-rate` / `max-i` / `deadband` **一律绝对设置**，负号就是取值本身（`--out-min -0.35` 是把输出下限设成 −0.35 rad，不是减 0.35）。不带参数的 `setpid` 打印当前双环增益全表（含单位与 `IsValid` 状态）；改完打印 old→new 对照表并提示「已生效」，`IsValid` 不过整体拒收并说明是哪一项。

### 整定期间的安全约定

- **Ctrl+C 任何时候都是急停**（清 `0x6040` + 断使能 + 锁存，退出码 130），整定视图不改这条；回车只是停止观察回提示符，**不急停**。`telemetry` / `watch` 不吃回车，仍按 `--seconds` 或 Ctrl+C 收。
- **参数热生效**：`setpid` 写的是影子缓冲，周期线程在下一拍首顶换，运行中就能调；改错了立刻再改回来或 `estop`。
- **`tune` 是只读命令**，任何已连接态都能看；未连接发 `tune` 给状态机拒绝（退出码 8）。
- 调参看趋势，别看单行：先把内环 φ 的 `dev` 与 `uφ` 收住。平衡外环由固定状态反馈给出，`Ka / Kad / Kai` 是历史参数，别在外环增益上找原因。`sat` 持续非 0 = 输出顶着限幅，先查 `--out-max` / `--out-min`；`miss` 持续增长 = 跟随误差超限，先把目标增量压下来（`setlimits --omega-arm-max`）。

## config.deni 是唯一配置真相


工具不生成、不改写、不用 ESI 冒充 DENI。

1. 在主站 GUI 里扫描真实从站（GCAN-8200 耦合器 + 步进驱动），导出唯一一份 `.deni`。
2. 放到 **exe 同目录的 `EtherCATRestore\`**（即 `bin\x64\<Configuration>\net472\EtherCATRestore\`；exe 同级放 `.deni` 也认，`--config` / `--deni` 显式指定优先）。注意 csproj 对源目录的 `EtherCATRestore\**\*.deni` 设了 `CopyToOutputDirectory=Never`——**把 `.deni` 放在本工程源目录不会自动复制到输出目录**，要放在输出目录那份 `EtherCATRestore\` 里。
3. `config.deni` **不可手工编辑**：它带 SHA-256 校验和逐字节 PDO / FMMU 启动指令，必须对应真实设备。改周期、改映射都要回 GUI 重新导出。

连接顺序：网卡解析（显式 `--nic` = 网卡名匹配 + 与 DENI Source MAC 校验；**不给 = 按 DENI Source MAC 自动匹配唯一网卡**，命中 0 张 / 多张一律拒连并列实况）→ 从站 Vendor / Product / Revision 与 DENI 对不上就 fail closed，不猜 → `SetENI + DisableAutoStartup + Build` → PreOp（回读 `0x1C12` / `0x1C13` 映射 + 结构体字节数校验）→ SafeOp（默认 `standard`；只有 `--op-entry direct` 诊断模式跳过显式 SafeOp）→ OP。**`connect` 建好总线并进 OP，但不使能**：不写 `0x6040`，输出保持断电；`enable` 只做 CiA 402 使能。

当前契约要求 DENI 给出：

- 总线周期 **500 µs**（`500000 ns` / 2000 Hz）。
- **DC 默认关闭（2026-11-20 实机）**。程序连接时默认不武装摆臂从站 DC（FreeRun；从站报告 DC 能力时显式 `DisableDC` 防止自动策略重新武装），不需要改 DENI；需要 SYNC0 时 CLI `--dc-sync` / GUI 环境变量 `FURUTA_DC_SYNC=1` 打开，优先级 **CLI 旗标 > 环境变量 > 默认关闭**，`--no-dc-sync` 覆盖环境变量的启用值。旧文曾按 EC1 ESI 的 `StartToSafeopNoSync=false` 推断“必须先配同步再切 SAFEOP”，**实机证明不成立**：把台架 DENI 的 `deni:DistributedClocks enabled=false`、步进 `HasDC=false`、`Sync0CycleNs=0`、`CycleTime=500000` 后，总线照样进 OP，使能耗时 **166 ms → 87 ms**。要开 DC 时仍按从站分别武装（`ConfigureDC(1000000, 0, null)`，以 `Sync0Armed` 为判据），GCAN 不参与 DC；但“无 DC 不能进 OP”不是事实。注意 `Slave.HasDC` 读的是 ESC 0x0008 bit2（硬件能力），不是 DENI 的 `HasDC` 字段。
- 非空的 `Master/Info/Source` 与非零 6 字节 MAC（**自动匹配就按它找卡**；MAC 拿不到 / 不是 6 字节一律拒连，不猜不夹）。
- 步进侧 RxPDO 只分配 `0x1600`（**7 B**，条目顺序 `0x6040 → 0x607A → 0x6060`），TxPDO 只分配 `0x1A00`（**17 B**，`0x603F → 0x6041 → 0x6064 → 0x606C → 0x60FD → 0x6061`），字段顺序与 `StepperRxPdo` / `StepperTxPdo` 结构体一致；**不要按旧顺序把 0x6060 放在偏移 2**。
- 计数侧按在位模块分配（对象字典 / 字段细节以 `--help` 与运行时诊断输出为准）：**GC1602（台架现用）** TxPdo `0x1A03`（两路 DINT 共 8 B）；ESI 声明 RxPdo `0x1600`（清零位 2 B），但当前固件上 `0x1600:00` 恒 abort `0x06020000`，主站探测到映射对象不存在就把输出方向按 0 配置（`GcanOutputsMapped=false`），**不要按 2 B 输出硬套**。**GC1502（兼容 / 备选）** TxPdo `0x1A03`（4×UDINT 共 16 B），RxPdo 无（无复位命令）。`0xF050` 末项 `0x00000001` 是结尾字符（不是模块），先剔除再按剩余真实模块累加字节数。0x1C12 / 0x1C13 允许多个 PDO，案例按分配顺序拼接条目核对；某一侧按真实模块推导为 0 字节时允许该侧 0 个 PDO。

## 易错点

- **500 µs 周期五条规矩**：① 等周期超时必须传 0（传 1 会把 500 µs 的拍合并成 ~2 ms，跟丢 SYNC）；② 线程保持 `Normal`，别抬到 Highest（UI/CLI 会饿死，抖动反而更差）；③ **漏拍不补跳**，相位/积分按拍数推进，目标 hold 上一拍值，绝不再按墙钟一次跳一大步；④ **算完即写**，`0x607A` / `0x6040` 必须在本拍算完写出，不许抛回 UI 线程、不许跨拍缓存待写；⑤ **回调里禁止日志**，字符串格式化、`Console.WriteLine` 一律禁止，诊断只在 1 Hz 节流里做。
- **`0x6040` 必须分步**：`0x06 Shutdown → 0x07 Switch On → 0x0F Enable Operation`，每一步都以 `0x6041` 实测状态为推进依据（`(sw & 0x6F) == 0x27` = OperationEnabled，`(sw & 0x6F) == 0x07` = QuickStopActive，`(sw & 0x4F) == 0x08` = Fault）。**本案例故障复位发 `0x0080`（bit7）**；若驱动器要求 bit2 保持 1，标准写法是 `0x0006 → 0x0086` 上升沿（只写 `0x0080` 会把 bit2 也清 0，部分驱动不认）。**禁止一次写成 `0x0F`**。停止分两条：`stop` 走**受控停**（`0x0002` Quick Stop 按 `0x6085` 斜坡减速 → 确认 QuickStopActive → `0x0000` Disable Voltage 回 SwitchOnDisabled；QuickStopActive 下直接发 `0x0006` 不是合法迁移），急停 / 故障 / 拆线才直接写 `0x6040 = 0x0000` Disable Voltage。拆线时 7 秒内必须有「请求 → 写入 → 更晚的状态回读」三段证据。
- **未使能时 `0x607A` 必须恒等于 `0x6064`**，否则一使能就跳变。使能前先过无运动门：连续 100 个新鲜 PDO 周期主从站保持 OP、WKC 匹配、状态可识别、`0x6064`（指令位置估计）不漂，才依次使能。**使能 ≠ 运动授权**：输出上电后目标保持起始位置 0（使能那拍已把两路编码器坐标归零，所以目标与实际同点、不跳变）。
- **摆臂是开环步进（EC1）**：`0x6064` 是驱动器内部指令位置的积分估计，不是电机轴实测；跟随误差、无运动门、阶跃护栏、软限位都只能做「指令 vs 指令估计」的一致性检查，**丢步 / 堵转 / 越障静默不可见**。唯一线索是 `0x603F = 0x8401` 位置超差（不可清除，S4 兜住）。真实机械安全靠硬接线急停 / STO / 机械限位，不靠软件软限位。
- **WKC 口径**：expected 是配置期固定真值，actual 如实读；本案例只用**自有两台**（GCAN + 摆臂）的响应判 S5，旁观从站掉 WKC 只进诊断、不触发 Fault。actual < expected 报警并逐轴定位，**不要**下调 expected、不要停 OP；WKC=0 也不等于线缆断了。
- **1 ms 会让 cyclic WKC = 0，进不了 OP**。周期由 DENI 定，改周期必须回 GUI 重新导出 DENI，不要在代码里改。
- **DC 不是进 OP 的前提（2026-11-20 实机）**。程序默认关闭摆臂从站 DC（FreeRun；从站报告 DC 能力时显式 `DisableDC`），需要时用 CLI `--dc-sync` 或环境变量 `FURUTA_DC_SYNC=1` 打开；关 DC 后仍能进 OP（使能 166→87 ms）；要开 DC 时 GCAN 不参与、摆臂 EC1 按从站武装 SYNC0，判据只认 `slave.Sync0Armed`（`null` = 结论未知），不写 EC1 的只读 `0x1C32:01 / 0x1C33:01`。**周期下限 500 µs**：250 µs（4 kHz）时 `InputsSliceMapping` 抛「PDO 输入映射不可用」，内核日志报「同一周期内重复通知同一个 PDO 输入缓冲区」；改周期必须回 GUI 重新导出 DENI。
- **摆臂每转计数来自 `0x2102` 细分 × 减速比，禁止猜 10000**：EC1 全系**没有 `0x608F`**（每转脉冲读不到，读不到是常态不是错误），唯一系数是 **`0x2102` 开闭环细分设置**（单圈脉冲数 P，200~60000）；`0x608F:01` 只在有该对象的机型做交叉校验。标定链 = 显式 `--arm-cpr` 为权威 → 不给则 `P × 减速比` 推导 → 都拿不到就拒绝运动并报差异。摆臂换算 `φ = (pos − φ_zero_count) × 2π / CPR_ARM`；摆杆换算 `θ = Δcount × 2π / CPR_PENDULUM`（Δcount = count − count_zero，走 **32 位回绕差分**——摆杆是往复运动、绕不满 2³¹，用 `long` 中间量做差即可），分母就是「摆杆每转计数」标定值（`--pendulum-cpr`），按切片口径取：GC1602（AB 正交）`CPR_PENDULUM = 线数 × 4 × 减速比`（AB 四倍频），GC1502（脉冲计数）= 每转脉冲 × 减速比（不乘 4），拿不准以运行时诊断为准；现场给值、不猜。**台架默认 2400 count/rev**（600 线 × 4，1 count = 0.15°；保持位 ±1200 count = 180° 直立，wrap 语义下 +1200 与 −1200 是同一个点）——旧的 600 是 GC1502 脉冲口径，已不再作为默认值。
- **EC1 无 `0x608F`，摆臂标定来自 `0x2102` 细分 × 减速比**：驱动器面板上改过细分（`0x2102`）就必须同步 `--arm-cpr`（或不给显式值、让控制层重推导），否则主站的电机侧每转计数与驱动器细分不对应，控制层**拒进 CSP 并报差异**（0x8402 根因①，手册 6.3 章）。改细分不改标定 = 一联调就卡在使能这一步。
- **`0x606C` 是 Pulse/s 幅值，不是 rpm、也不是带符号速度**：按 rpm 换算会把摆臂速度放大 `CPR_ARM/60`（10000 细分 = 166 倍），低速段还有 1000 Pulse/s（0.628 rad/s）的量化台阶。换算只走 `ControlMath.ArmRadPerSecFromDrivePulsePerSec`，控制律的 φ̇ 一律用 φ 差分。详见「控制语义」里那一条。
- **参数单位看清楚**：起摆「泵加速度幅」是 **rad/s²**（往复泵加速度幅值），**不是角度、不是 0~90°**。`θ_trip` / `θ_lost` / `φ_err` 等安全阈值都是 rad，界面上按度显示，命令行给原值。
- **每拍目标增量有护栏**：`0x607A` 相对上一拍的增量受 `ω_arm_max × dt` 限制，阶跃过大会让驱动报 `0x7500`（CiA 通讯类错误）。
- **SDO 只在连接 / 配置阶段用**，别塞进周期路径，会卡住 500 µs 周期。
- **命令行不是 2 kHz**。控制台扛不住 2 kHz 输出，`telemetry` 默认 1 Hz、上限 20 Hz；2 kHz 的真相在日志文件和遥测环形缓冲里。

## 安全约定

- **上电即安全**：进程启动不做任何自动连接、自动使能、自动起摆；`connect` 只进 OP、不写 `0x6040`，输出保持断电。
- **未使能不动**：使能前目标恒等于实际位置；使能后目标保持起始位置 0，直到明确起摆。
- **急停永可点 / 永可按**：UI 的「急停」任何时候都亮；CLI 里 Ctrl+C 就是急停，插队执行、不需要 `--yes`、任何状态都合法。
- **硬接线急停 S11 / STO 不被软件替代**。软件 `0x6040 = 0` 只是断输出，不是安全回路。
- **θ 超限自动联锁锁存**：摆杆偏离直立超过阈值、平衡丢失、跟随误差超限、总线反馈不可信、硬急停断开等都会立刻 `0x6040 = 0` 进故障并锁存。
- **故障复位后必须重新起摆**：复位只回 `Stopped`，不自动回平衡、不自动回起摆——现场不知道摆杆周围有没有人。
- **零点靠使能自动归零，`zero` 只是重标定**：`enable` 成功即把两路编码器坐标归零（θ = 0 = 摆杆自然下垂、φ = 0 = 起始位置）。手动 `zero`（UI「角度置零」/「设置 0 点」；CLI `zero pendulum` / `zero arm`）是校正手段，**需要人在机械旁边**（CLI 归为危险命令，要 `--yes`）：摆杆零点仍须在自然下垂位；摆臂 0 点可以点动到期望位置后直接设置（UI 的「设置 0 点」在点动中 `Enabled` 也可用，控制层下一拍换基准并平移目标，位置指令不跳变；起摆 / 平衡中拒绝），CLI `zero arm` 仍只在已连接 / 已停（未使能）合法。**CLI `zero` 成功后会自动写盘**（`persisted`）；UI 采集仍要显式「保存参数」。位置不对清出来的坐标全错；漂到一侧后不要反复 `zero arm`，用 `normalize` / `recenter`（见「控制语义」）。

## 分步操作

### UI 跑法

1. 把现场 GUI 导出的 `config.deni` 放进 **exe 同目录的** `EtherCATRestore\`（`bin\x64\<Configuration>\net472\EtherCATRestore\`，目录里有说明 txt；只放一个 `.deni`，多个会被拒绝）。
2. 双击 `FurutaPendulum.exe`（或 `--gui`）。窗口可自由缩放：只钉最小客户区 1280 × 1000（三行八张卡片都放得下），不设上限，拉到多大各区块都等比跟着长。
3. **连接**（进 OP，但不使能）→ **使能**（CiA 402 `0x6040` `06 → 07 → 0F`）→ **起摆**：点一次就进入全自动甩摆，硬捕获门 + 提交臂速 / 摆杆角速度软上限满足且漏桶计数计满时**自动切入平衡**——界面没有「平衡」按钮，起摆成功后不需要再点第二次。
4. 停：点「停止」受控停（目标斜坡收回、`0x6040 = 0`）；任何异常点「急停」；收工点「断开」。
5. 主视野是**一张单页**：左栏操作 / 状态，右侧三行八张卡片——第一行「PDO 实时数据」+「总线与采样」+「当前状态」，第二行「杆角度表盘」（左列跨两行，占两格）+「PID 参数」+「设备参数·软限位」，第三行「角度读数」+「运行日志」，没有页签。在「PID 参数」卡上 **Ka / Kad / Kai（杆角 θ）** 是历史参数、只读（平衡环由固定状态反馈接管，调整不参与平衡；旧值仍随参数文件读写），可改的是**泵增益 k_e / 泵幅度 / 泵频 / 相位偏移**；**内环 Kpφ / Kiφ / Kdφ（关节位置修正）**、**加速度 / 角速度限幅 AccMax / ArmRateMax**（平衡态再与内置 350 rad/s² / 24 rad/s 取较小值）、**起摆与切换（能量增益 ε / 起摆 AMax / 切换 θ·ω / 捕获臂速上限 / 起摆回中 Kφ / 起摆阻尼 Kφ̇ / 抽取增益 ExtractGain / 软中心带 CenterBandRad）**、**摆臂角速度上限 ω_arm** 点本卡「PID 调参…」在同一个「控制参数」对话框里改，点「确定」立即下发控制层（控制层每拍顶换；非起摆态运行中也可改，起摆中仅「抽取增益 ExtractGain」与「软中心带 CenterBandRad」可改，其余起摆七项锁定；不写文件，落盘用左栏「保存参数」）（对话框内另有「自动调参…」入口，见下）。改动立即对本次运行生效（文本框 250 ms 去抖；平衡外环三项与对话框里的平衡 Kφ / Kφ̇ 均为历史参数、只读；泵参数只在非起摆态生效，起摆中拒收并在状态行提示），但**不再隐式落盘**：有未保存改动时「保存参数」按钮显示「保存参数 ●」并变橙，状态卡「参数」行显示「未保存（已生效）」。左栏「参数」卡四个按钮 = **保存参数 / 应用（不保存） / 载入参数 / 恢复默认**：「应用（不保存）」先把还没跑完的 250 ms 去抖编辑强制提交，再把 PID / 泵 / 软限位重新下发控制层，不写文件；「保存参数」才写 `furuta_params.json`（含本次生效的 DENI 路径作溯源、软限位、标定、辨识结果与捕获记录），成功时状态行显示**完整路径**（exe 目录不可写时会带回退说明），失败显示原因 + 目标路径；关窗仍做一次兜底保存。「载入参数」读回并应用（**只在未连接 / 已连接 / 已停可点**，运行态置灰），成功后清除未保存标记。**GUI 启动会自动载入这份文件**；保存是原子写（临时文件 + 替换）。
   - **自动调参…**（主界面「PID 调参…」对话框里的入口）：流程 = 前置检查 → 采集自由摆动 8 s → 识别 → 计算候选增益（`ω_c = 2ω_n`、`ζ = 1.2`、`Ka = g/l + ω_c²`、`Kad = 2ζω_c`）→ 试跑验收（起摆上限 = `swingup.timeout_ms`（默认 180 s）+ 20 s 余量，本台架慢起摆 150 s 量级属正常；平衡保持 ≥5 s、最大偏差 ≤15°、平衡中 >30° 判发散）→ 采用并保存 / 回滚；失败 / 超时 / 取消自动回滚到调参前整组参数。**平衡环由固定状态反馈接管后，算出的 `Ka / Kad` 只作记录、不写入控制层，实际下发的是起摆泵参数。** 详细规范见 `内部文档/参数与调参规范.md`。
6. **点动**：按住「◀ 点动 / 点动 ▶」才动，松开即停（只在已使能 [就绪] 态有效）。**点动不受软限位约束**：软限位只在起摆 / 平衡等自动运动里做目标钳位；点动只受 `JogSpeedRadPerSec = 1.0 rad/s` 与每拍增量 / slew 速度护栏管（现场必须靠点动把关节开出旧限位，才能采集左右限位和零点）。关节位置读数只给原始计数：绝对 `0x6064` 与相对零点的偏移。
7. **恢复默认**（左栏「参数」卡）把平衡 PID / 能量泵恢复默认并清空参数自测结果，同时标记未保存；**标定、软限位、捕获记录保留**（软限位是实测出来的位置，不会被默认值覆盖）。运行中该按钮置灰，避免换参数猛甩关节。
   - **没有「平衡」「系统辨识」「测量流程」「整圈捕获」按钮**：平衡由起摆判据自动切入；参数自测并入起摆（起摆开始回灌泵频、切平衡时自动 `IdentifyNow()` 并应用推荐泵频 / 泵幅 / `k_e`）；整圈捕获只作为控制层内部历史记录能力，界面不显示、不提供入口。
   - 状态卡「参数」行常驻显示保存状态：已落盘时 `参数已保存 HH:mm:ss`，有未保存改动时 `未保存（已生效）`。**5 个位置采集 / 内环调参与限幅 / 泵参数 / 恢复默认 / 起摆结束自测结果都只对本次运行生效并标记「待保存」**，不会自动写盘；只有显式点「保存参数」（或自动调参「采用并保存」）才落盘，关窗仍做一次兜底保存。

### 设备参数 / 软限位（5 个位置，全部按原始计数）

「设备参数 / 软限位」卡是现场标定与软限位的唯一入口。参数只有 **5 个位置**，每个位置 = **一个采集按钮 + 一个绝对 counts 输入框**：

| # | 按钮（取当前值） | 输入框 | 说明 |
|---|---|---|---|
| 1 | 左限位 | 左限位 counts | 绝对 `0x6064`；要求 左 < 驱动臂零点 < 右 |
| 2 | 驱动臂零点 | 驱动臂零点 counts | 驱动臂坐标 0（改它不搬限位） |
| 3 | 右限位 | 右限位 counts | 绝对 `0x6064`；左右可不对称 |
| 4 | 摆杆零点 (下垂 0°) | 0° counts | 摆杆自然下垂 / 最底部的原始计数 |
| 5 | 摆杆 360° | 360° counts | 从 0° 点整转一圈后的原始计数 |

- **一圈的量 = |360° − 0°|**，由两点标定算出，界面**只显示结果，没有输入框**。
- **没有任何角度 / 度 / 比例 / 细分 / 每圈计数 / 「绝对定位」输入**：摆杆角度只由 counts 推导显示并归一化到 [0,360)，不参与任何判定。
- 输入框不设角度 / 行程量程（int32 全域）；校验只有「整数」与「左 < 驱动臂零点 < 右」、摆杆两点不相等。
- 采集按钮任何状态都可点；没有实时计数 / 状态不允许时，状态行与日志给中文原因。**「驱动臂零点」在点动中（`Enabled`）也可用**（标准流程：点动到期望中心 → 设零点，或直接在该位置使能——每次使能会自动重新锁零），起摆 / 平衡 / 整圈捕获中拒绝。
- **驱动臂零点只是坐标原点**：左右限位是绝对 counts，改零点**不移动限位**；改零点或限位时按三点关系校验，越序直接拒写并说明。**反复 `zero arm` 会越跑越少行程**：每次在偏一侧的位置设零，坐标原点就往那一侧搬，另一侧剩余行程变小，最后必然撞限位。恢复用 `normalize`（零点 + 左右限位一起平移、跨度不变）或 `recenter`（先开到行程中点再居中规整化）；UI 对应「规整化左中右」/「规整化摆杆」，CLI 对应 `normalize` / `recenter`（都会自动落盘）。
- 参数落盘：5 个值 + 派生的一圈的量写进 `furuta_params.json`（`limits.arm_min_count / arm_max_count`、`soft_limits.min_counts / max_counts`、`calibration.arm_zero_count / pendulum_zero_count / pendulum_360_count / pendulum_cpr`）；旧文件里的 deg 字段一律忽略，缺 counts 就提示重新采集，**不按比例推算**。**CLI `zero` / `normalize` / `recenter` 自动写盘；UI 采集按钮仍只改内存，要点「保存参数」。**

### CLI 跑法

```powershell
# 脚本化验收：一条命令跑完整套，状态在同一个进程里保持。
# --pendulum-cpr 是摆杆现场标定值（按 GC1602 AB 四倍频口径，台架 2400 = 600 线 × 4；不给 = 默认 2400，显式给 0 = 未标定则拒绝起摆）；
# --arm-cpr 是摆臂每转计数（电机每转计数 × 减速比，本例 = 10000 × 2），不给就按 0x2102×减速比 推导；
# --arm-slave 指定摆臂从站（1 基）。enable 会自动归零（θ=0=垂位，φ=0=起始位），不需要先手动 zero。
```

读回优先级：`pump` 段覆盖 `swingup` 的泵相关字段（`pump_amp_deg` 是**等效摆臂角幅值**，按 `A_acc = A_deg·(2πf)²` 换算成控制层的 rad/s²；`phase_offset_deg` 换算成 rad），`soft_limits` 段与 `limits.arm_min_count / arm_max_count` 是同一对绝对 counts，`soft_limits` 优先；旧文件的 `min_deg / max_deg / phi_min_rad / phi_max_rad` **一律忽略、不换算**，缺 counts 时提示重新采集。`calibration.pendulum_cpr` 在 0°/360° 两点齐全时**按 |360−0| 重新派生**（覆盖文件值），只在 GUI 启动自动载入时恢复（且本次未显式给 `--pendulum-cpr`；文件里的旧 600 会在那时迁移成 2400 并留警告）——**CLI 的 `load-config` 运行期不恢复标定**（只恢复 PID / 泵 / 软限位），CLI 要改 `pendulum_cpr` 必须显式 `--pendulum-cpr`；构造期摆臂标定例外：入口（`Program`）在未给 `--arm-gear` / `--arm-cpr` 时从同一份参数文件（默认文件或 `--config`）读回；`calibration.arm_counts_per_rev` 是参数文件兜底值，**CLI 未给 `--arm-cpr` 时也用它作构造期兜底**（运行时 0x2102 实读仍是权威）；`calibration.arm_gear_ratio` 只在启动构造期生效。可选段坏了只回退该段并在状态行 / 日志提示，**不拖垮三段必需参数**；三段必需段坏了也**不再整份拒载**——`swingup` 段逐字段修复（只换越界那一项），`pid` 段整段回退，`limits` / `soft_limits` 里缺 counts 或三点（左 < 零点 < 右）越序时把软限位对重置为「尚未采集」占位并告警（其余阈值仍走原校验），其它段照常生效，每一处都写进 `load-config` 的 `! warning`（字段、读到的值、生效的默认值、原因）。捕获记录按时间排序只留最近 20 条。

保存时机：**UI 只有显式动作才落盘**——点「保存参数」、自动调参试跑通过后点「采用并保存」、以及关窗兜底（`OnFormClosing` 仍保存一次）。5 个位置采集 / 参数框失焦 / 回车 / 内环调参与限幅 / 泵参数 / 恢复默认 / 起摆结束自测结果都只对本次运行生效并标记「未保存（已生效）」，不写文件。CLI 除显式 `save-config` 外，`zero` / `normalize` / `recenter` / `calibrate-radius` 成功后也会自动增量落盘（回执 `persisted`）——它们改的是标定 / 几何量，不落盘下次使能就会判不一致。保存是**原子写**（写临时文件再替换，断电不留半截 JSON）；GUI 启动会自动载入这份文件，CLI 仍用 `--config` 显式载入。

三段必需段的校验失败按「起摆段逐字段修复、PID 整段回退、安全阈值整段回退（软限位缺 counts / 三点越序时重置为尚未采集占位并告警）」处理，可选段逐段回退（见上），都不写一半、不静默；只有文件本身读不出来（JSON 解析失败）、缺必需段、或 `format` 不认识时才整份拒载。参数改动热生效（下一拍顶换），运行中换整套参数文件只允许在 `Disconnected / Connected / Stopped`（CLI `load-config` 与 UI「载入参数」同一道门）。保存是原子写，不留半截 JSON。现场调试顺序照这个来，别一起调：先单独调摆臂内环 → 看摆杆角速度曲线干不干净 → 平衡外环由固定状态反馈给出、不再调整（`Ka / Kad / Kai` 是历史参数）→ 最后调起摆能量增益；**不要靠放宽切换判据来凑起摆成功**。

## 已知问题（2026-11-20 实机）

- **平衡只维持约 0.26 s 就发散**：起摆能进提交条件并切平衡，但平衡接管后约 **0.26 s** 触发 `ThetaOverrun` / `BalanceLost`。已排除：增益大小、符号、捕获臂速门限、执行权限、结构稳定性（`r/l=0.24 / Ka=900` → `(r/l)·Ka=216 > g/l=81.8`，2.6 倍裕量）。原因未定位；**不要把本轮的起摆提速 / 漂移改善当成“平衡已经可用”**。
- **UI 的「摆杆零点」采集不搬 360° 点**：它只改内存里的 0° 点，重标后要重采 360°（或清空重采）；CLI `zero pendulum` 落盘时会按同一圈量自动平移 360° 点（回执 `pendulum360Rebased` / `calibrationNote`），不受这条限制。
- **250 µs（4 kHz）不可用**：`InputsSliceMapping` 抛「PDO 输入映射不可用」，内核日志报「同一周期内重复通知同一个 PDO 输入缓冲区」；周期下限 **500 µs**。
